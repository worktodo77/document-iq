# Sprint 3 — measuring the three unruled items in the section taxonomy

**Date:** 2026-08-17
**Branch:** `build/sprint-3`
**Probe:** `tools/measure_sections.py`
**Artifact:** `docs/verification/artifacts/sections_2026-08-17.json`
**Corpus:** the real MODEC/Petrobras record (D-12), read-only — 298 PDFs, 17,732
pages, 0 unreadable. Client data: no page text, no document name and no file
from the corpus appears here or in the artifact.

`docs/design/section_taxonomy.md` §6 left four things unruled. One (the approver
problem) is a decision and was ruled as **D-34**. The other three are questions
about the corpus, and this is the measurement. D-18 is the precedent: *measure
it properly first.*

The page count reproduces D-12's independently-established 17,732 exactly, which
is the cross-check that the probe is reading the corpus the rest of the
programme measured.

## Q1 — Tier 1 (the document's own PDF outline)

| | |
|---|---:|
| Documents carrying an outline | **89 of 298 — 29.866%** |
| Outline entries | 3,538 |
| — of which name a position, not a section | 226 |
| Pages **placed under a name a rule could key to** | **11,173 — 63.01% of the corpus** |
| Distinct labels, raw | 716 |
| **Distinct section families** (numbering stripped) | **522** |
| — carrying project-identifying text | **159 — 30.5%** |
| Documents with a non-monotonic outline | 4 |

**The taxonomy's "40% of the PDFs carry a PDF outline" is high.** It came from a
36-document sample; over all 298 the figure is **29.9%**, ten points lower.

**And the document percentage is the wrong number to carry forward.** Outlined
documents are the large ones: 11,401 of the corpus's 17,732 pages sit in a
document that carries an outline. So a tier present in under a third of
documents reaches **nearly two thirds of the pages**, and Tier 1 is the
workhorse of this design rather than a best case. Both figures belong in any
statement about Tier 1, because quoting either alone misleads in opposite
directions.

**A distinction this probe added, and the honest report of how much it
mattered.** Smoke-testing surfaced PowerPoint-exported PDFs whose every outline
entry reads `Slide Number 33` — an outline that *places* a page while naming no
section, which would count as Tier 1 coverage and give a rule nothing to key to.
The probe was changed to measure pages placed under a **substantive** name, and
a page whose governing entry is positional is excluded.

Measured, that concern is **small: 226 of 3,538 entries (6.4%)**, and no document
in the corpus has a positional-only outline. It was worth separating and it did
not change the picture — recorded that way round rather than presented as a
catch. **The first version of the check missed 76 of those 226**: normalization
turns the outline entry `5.1` into `5 1`, which an anchored `\d+$` does not
match, so entries naming nothing but a section number were counted as names a
rule could key to.

### The vocabulary, and the two things in it that bind the template design

**522 distinct section families** — the count after numbering is stripped. Raw
it is 716, and the entire difference is `4.5 ENGINEERING` versus
`5.4 ENGINEERING`: the same section under a different number in a different
month's report. 522 is still far too many to enumerate in a shipped template, so
a template must key to a **normalized family**, not a list of literals.

**159 of the 522 — 30.5% — carry project-identifying text.** `BOMESC YARD` (48),
`COSCO TOPSIDE YARD` (48), `MV32 APPENDICES` (33), `STATUS OF PETROBRAS TQ` (24).
D-24 forbids a template attributable to a corpus project, so a template matching
these verbatim would compile `MV32` into a Long International deliverable.
Project tokens must be stripped before matching, and **the token list must be
supplied per matter rather than shipped** — which is why `--project-tokens` is a
run-time flag on this probe and no project name appears in its source.

**The third most frequent label in the corpus is Portuguese.** `PAGINA EM BRANCO`
— blank page — 61 occurrences. An English-only template does not see it, and it
is a drop candidate. Matching must be accent-folded and templates must be able
to carry non-English patterns; nothing may assume the record is in English.

## Q2 — Tier 2 (parsing the table of contents)

§6's stated doubt: *"TOC page numbers may not match PDF page indices where front
matter is unnumbered."*

| | |
|---|---:|
| Documents with a TOC page | **275 of 298** |
| Documents with both a TOC and an outline | 82 |
| TOC lines parsed | 10,041 |
| Lines safely paired to an outline entry | 106 |
| Documents yielding ≥1 safe pairing | 25 |
| **Offset (printed number − physical page)** | **0, in all 106** |
| Documents where the offset is constant | **25 of 25** |
| Documents where it is scattered | **0** |

**§6's doubt is not reproduced.** Wherever it could be checked, the printed page
number *is* the physical 1-based page, and the within-document spread is zero
everywhere.

### Read this before using that result

**The check can only reach documents that do not need Tier 2.** Pairing a TOC
line to ground truth requires the document to carry an outline — so the 25
documents measured are drawn from the 82 that have *both*. The population Tier 2
exists to serve is the **~193 documents with a TOC and no outline**, and this
method is structurally incapable of reaching a single one of them. The result
lowers the risk; it does not close the question, and Tier 2 remains unbuilt and
unvalidated on its own population.

**Two instrument corrections, recorded because the first version's number was
published to nobody but would have been wrong:**

1. The first run paired **3 lines out of 3,484** and looked like a decisive
   result against Tier 2. It was a comparison bug: a TOC prints
   `3.1 EXECUTIVE SUMMARY` where the outline says `EXECUTIVE SUMMARY`. Stripping
   leading section numbering pairs 103. **A red result from a broken instrument
   is not evidence**, and this one would have descoped a tier.
2. Pairing stops at numbering-stripped equality deliberately. A substring match
   pairs 1,292 of the same 3,484 lines, and `PROGRESS` is a substring of six
   distinct section names in this corpus — that would manufacture offsets rather
   than measure them.

**One claim that looked implausible and was checked rather than asserted:** 275
of 298 documents carrying a TOC page seemed too high, and the suspicion was that
`TABLE OF CONTENTS` was matching a running header on every page. It is not — a
per-document count over 40 documents returns 1–3 TOC pages each, never a whole
document. The detector is sound and the instinct was wrong.

## Q3 — coverage of the documents Tier 1 cannot serve

Tier 3's rules as §3 states them, transcribed and run over the 209 documents
without a substantive outline (6,331 pages).

| Tier 3 class | Pages |
|---|---:|
| Photo / figure | 585 |
| Table of contents | 373 |
| Schedule / activity table | 303 |
| Distribution list | 32 |
| Image-only | 15 |
| **Resolved by some rule** | **1,308 — 20.66%** |
| **Resolved by nothing** | **5,023 — 79.34%** |

**Four pages in five, in the documents that need Tier 3 most, resolve to
nothing.** Under the KEEP-by-default contract that is a safe outcome and a
correct one — those pages survive — but it settles what Tier 3 is: a
supplement, not a fallback that catches the corpus.

### The corpus, whole

| | Pages | Share |
|---|---:|---:|
| Placed by a Tier 1 outline, under a name | 11,173 | 63.01% |
| Resolved by a Tier 3 page class | 1,308 | 7.38% |
| **Recognized in total** | **12,481** | **70.39%** |
| Front matter, and pages governed by a positional entry | 228 | 1.29% |
| Resolved by nothing, in unoutlined documents | 5,023 | 28.33% |
| **Unrecognized — kept unconditionally** | **5,251** | **29.61%** |

**About 70% of the record can be placed in a section; about 30% cannot, and is
kept.** That is the honest ceiling on the reduction feature for this corpus, and
it should be the claim the product makes.

### Limits of Q3's figures

- Tier 3 has **no implementation in the build**. These rules are transcribed
  from §3's prose into the probe. The thresholds are the design's own (≥12
  dates, <300 characters, ≥25% image area); a different threshold moves the
  number, and none has been tuned against hand-checked ground truth.
- The classes are counted **first-match-wins in §3's order**, so a page that is
  both a schedule table and photo-bearing is counted once.
- Photo/figure at 585 pages is a **page-count** figure. D-27 and §5 already
  establish that photographs are 0.2% of the text; nothing here revises that,
  and none of these page counts should be read as token savings.

## Found while measuring: the shipped Stage-4 engine drops the wrong pages

Not part of §6, and more urgent than any of it.

`profiles/apply.py` matches a rule's regex against **every line of every page**
and carries the matched section forward until another rule matches. So a rule
written for a real section also fires on any line that merely *mentions* that
section, and the carried state then governs every following page.

Reproduced on four independent trigger shapes, with a single DROP rule for
`PROGRESS PHOTOGRAPHS`:

| Trigger | Pages dropped | Expert meant |
|---|---|---|
| The document's own table of contents | 2–7 | 6–7 |
| A body-text cross-reference | 2–4 | none |
| A transmittal listing enclosures | 1–3 | none |
| An appendix cover sheet | 2–3 | none |
| **A correct first match, no rule marking the section's end** | **1–4** | **1–2** |

The last row is the worst and needs no confusing text at all: one correct rule,
and the drop runs to the end of the document. In the reproductions the pages
lost are the **executive summary, the critical path narrative, the weather log
and the timesheets** — four of the categories §4 grades HIGH risk — and the drop
log attributes every one of them, fully and wrongly, to `PROGRESS PHOTOGRAPHS`.
The audit trail is complete and it is a misdescription.

This violates §1's binding asymmetry directly: *a section the recognizer misses
is a page that survives; a section it invents is a page that vanishes.* Here the
recognizer invents.

**Exposure today, stated precisely.** `apply_profiles` is wired into the real
pipeline at `pipeline.py:1435`, and no test covers the carry-forward path. But
**no built-in profile ships and there is no profile YAML on disk**, so the code
is reachable only by a hand-authored profile in the D-05 library, and nobody has
authored one. The defect is live and unexercised — which is precisely why it has
to be settled before templates ship, since templates are the thing that would
make it exercised on every run.

**Ruled the same day: D-35 — replace, not repair.** Section resolution moves to
Tier 1–3 page *spans* and Tier 4 explicit ranges; regex heading matching and
carried section state are deleted. The alternative considered and rejected was
suppressing matches on TOC pages, which is the repro fix for one of five
observed shapes.

## Reproducing this

```
PYTHONPATH=src .venv/Scripts/python.exe tools/measure_sections.py \
  "<corpus root>" --out docs/verification/artifacts/sections_2026-08-17.json
```

Deterministic given the same corpus: the probe sorts its inputs and does no
sampling.

**Three full runs were made, and the figures here are all from the third.** Run 1
carried the exact-label pairing bug. Run 2 fixed it, and its Q1/Q3 figures were
byte-identical to run 1's, which is what a pairing-only change should do. Run 3
fixed the positional-label check (`5 1`) and added the vocabulary and
project-token measures; it moved `pages_placed` by one page (11,174 → 11,173)
and the positional count from 150 to 226. **Any figure quoted from runs 1 or 2
elsewhere is superseded by this document.**

**No timing figure is quoted in this document.** Machine load was not controlled
during these runs and every number here is a count, not a duration.
